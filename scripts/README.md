# scripts

One line per script: name, what it does.

Dependencies: "standard library only" in a script header describes what it uses today, not a rule. Adding dependencies is fine (pin them in `requirements.txt`, install into `scripts/.venv`). Only `gtr2-setup.py` is stdlib-only on purpose (it runs before the venv exists). `gtr2_ui/nav_client.py` is stdlib-only for a faster start, which is optional (a start under 1 s is fine).

- `../Tools/DocumentsGTR2.ps1` – compare (or with `-Update` create/refresh) the `_DocumentsGTR2/` snapshot in the game folder (`-Root` or `GTR2_ROOT`) against the live shared `Documents\GTR2`; exit 1 on differences. Predates this folder; new scripts go here.
- `gtr2-clean-slate.ps1` – move the shared `Documents\GTR2` and all `UserData\<profile>` folders into a timestamped `Documents\GTR2_ASIDE_*` folder for a first-run test (`-DryRun` to preview).
- `gtr2-launch.ps1` – run GTR2.exe (or `-Program GTR2Config`) with the game folder's `config\Documents-Config.ini` (created on first run) swapped into `Documents\GTR2` (relative data paths, so all data stays here), then restore Documents byte-for-byte; lock + running-process guard, `-DryRun`, `-KillAfter`, `-AdoptConfig`, `-InitConfig`, `-Restore`.
- `gtr2-set-resolution.ps1` – pick a resolution by its text in GTR2Config (`-List`, `-Resolution WxH`, `-DryRun`, read-only `-Status`, `-Dropdowns` (list every GTR2Config drop-down and its options), `-Shader`/`-Select id=regex` (choose by text), display-scale aware via `-Scale`), store it in `config\Documents-Config.ini`, then **verify by launching** (window client exactly WxH, desktop unchanged); `-VideoMode N` writes a known index directly when the dialog saves a wrong one (`-Offset N` is experimental); failure restores the previous config.
- `gtr2-drive-lap.py` – drive a lap hands-free with the keyboard from the game's telemetry and the track's AIW waypoints (standard library only today; control loop and presets in `gtr2-drive-lap.py`, telemetry and track reader in `gtr2_driving/`). Open Practice and Time Trial; needs the keyboard driving profile described in `CLAUDE.md`. `--dry-run` reads telemetry only.
- `gtr2-accel-challenge.py` – scripted standing start for Driving School "Basics - Acceleration, Level 1" (waits for the GO text, 1st gear, throttle, speed-gated upshifts). Passed with GOLD (13.914 s) once the launch was timed with a fixed `--go-delay`; needs the keyboard driving profile applied. `--aiw <layout .AIW>` steers along the racing line (keeps the wet Anderstorp run on the line; the wet Level 4 still resets at x about 35 m, see CLAUDE.md).
- `gtr2-nav.py` – scripted GTR2 menu navigation (needs `scripts/.venv`, see `requirements.txt`): `ready`, `where`, `goto PAGE LABEL`, `path FILE` (`PAGE | LABEL [| EXPECTED]` lines from `nav_paths/`; checks the source page, presses by the menu map, waits for the destination page by image recognition), `learn FILE` (saves this machine's reference image for pages that differ from the shipped ones), `exit` (EXIT + confirm), `pause [ROW [--enter]]` (pause-menu highlighted row, ported reader in `gtr2_ui/pausemenu.py`), `watch` (kills the game on a display change, time limit or Ctrl+Alt+End), plus `click`, `measure`, `sweep`. Hover/hold/release 30 ms minimum; about 0.35 s per verified page. Run: `scripts\.venv\Scripts\python.exe -I scripts\gtr2-nav.py path scripts
av_paths	our_options_main.txt`.
- `gtr2_ui/` – `menumap.py` (reads `UIData\gtr2ui.mnu`), `pagerec.py` + `baselines/1280x720`, `paths.py`.
- `requirements.txt` – pinned numpy, Pillow, mss for the venv (`python -m venv scripts\.venv` then `scripts\.venv\Scripts\pip install -r scriptsequirements.txt`).
- `gen-nav-tours.py` – writes `nav_paths/tour_setup_*.txt` and `tour_session_*.txt` (session tours need `gtr2-nav.py path --session-step`; Practice, Race Weekend, 24 Hour, Time Trial, Driving School, Championship setup pages) from a built-in tour list, validated against the menu map; `--dry-run` previews. Run with the venv python.
- `gtr2_ui/coords.py` – the measured slider, list and switch positions (UI units); used by `gtr2-nav.py drag|slider|row|scroll`. `gtr2_driving/track_params.json` – per-track driving options applied by `gtr2-drive-lap.py`.
- `gtr2_ui/nav_client.py` - stdlib client that forwards `gtr2-nav.py` commands to a background server (`serve`/`stop`; about 180 ms per command). `gtr2_ui/coverage.py` - how many menu pages have references and tours (`--list`, `--entries`). `gtr2_ui/pair_scores_1280x720.json` - committed twin-page score cache (`gtr2-nav.py index` after learn or refine).
- `gtr2-nav-suite.py` - launches the game, runs every navigation tour in order (flags read from each tour's header), closes the game via its menus, reverts the profile and checks `Documents\GTR2`; `--learn` learns the reference pictures for a test size other than 1280x720 (setup offers it); table of results, exit 0 only if all pass. `--dry-run` shows the plan. About 2 minutes, no model involved.
- `test_nav_guards.py` - offline safety tests for `gtr2-nav.py` (41 tests, 0.2 s, no game): every menu-map button against every opt-in flag, position labels, popups, LAN and host rules, tours against their header flags, drag release, pause-row reader. Run: `scripts\.venv\Scripts\python.exe -I scripts\test_nav_guards.py`.
- `nav_paths/tour_race_weekend.txt`, `tour_replay.txt`, `tour_race_24h.txt`, `tour_champ_round.txt` - hand-written tours that race on the game's autopilot (`gtr2-nav.py path --session-step --drive-step FILE`; the round tour also needs `--season-step`): `!SHORTRACE`, `!SHORTENDURANCE`, `!SHORTCHAMP`, `!NEXTSESSION`, `!RACE` steps, post-race pages, replay studio. All are in the suite's ORDER.
- `nav_paths/tour_champ_custom.txt` - RESTART on the Custom championship tab and back (needs `--season-step` and the empty `SDNDTG.DYN` in the install root, which unlocks every custom championship; the suite skips it without the file).
- `gtr2-control-check.py` - value-level control test: runs `nav_paths/controls_*.txt` (made by `gen-controls-tours.py`) one game launch each, clicks every checkbox and spinner of the Options, Audio, Advanced and Realism pages (`!CONTROLS`, needs `--setting-step`), closes the game, compares the profile the game wrote with git (every control that changed on screen must have saved its key) and reverts. `scripts\.venv\Scripts\python.exe -I scripts\gtr2-control-check.py [--only main,school,practice,24h]`.
- `gtr2-hover-check.py` - hover over every button of every page the suite's navigation tours reach (no clicks) and write `gtr2_ui/hover_silent.json`: the buttons that do not visibly react (greyed, inert, own tab). About 8 minutes. `gtr2_ui/diag.py` - preflight checks and failure diagnostics behind `gtr2-nav.py preflight` and `diagnose`.
- `gtr2-file-watch.py` - report every time the game opens given files during a run (read-handle oplocks, no admin; `gtr2_ui/oplock.py`), optionally running tours and a one-run `--plr "Key=value"` profile tweak.
- `gtr2-weather.py` - `apply|restore|status|run sunny|rainy|stormy`: copy a weekend weather file (`config/weather/`) over `UserData\LOG\weather.txt` and set Weather to 0 for the Race Weekend, Practice, Time Trial, Championship and 24 Hour, then put everything back.
- `gtr2-lap-check.py` - hands-free lap check: sets the profile (keyboard driving keys, layout, car), launches, Open Practice, DRIVE, `gtr2-drive-lap.py --fast`, back out through the menus, reverts; clean = completed and under 0.5% off the road. `LAYOUT [--car KEY] [--runs N]`, `--all-layouts`, `--all-cars`, `--resume`, `--list`, `--list-cars`. 3 to 7 minutes per lap.
- `gtr2_driving/vjoy.py` - stdlib ctypes wrapper for the vJoy virtual joystick (device 1; `VJoy(1).axis("X", 0..1)`); `python -I scripts/gtr2_driving/vjoy.py sweep X` to test. Driver installed once with admin; game sees it as JOY1 (default Y-/Y+ = throttle/brake on one axis, X = steering; progress bars on Controls > Buttons show the input).
- `gtr2-setup.py` – guided first-time setup (`--check-deps` only lists the requirements and what this machine has; see `../DEPENDENCIES.md`): detects/asks for the game folder, profile, window size, creates the venv, git-tracks the game folder, runs the bootstrap launch and window-size check, writes `gtr2-tools.json` (`--dry-run`, `--yes`, `--suite`).
- `gtr2-crash-report.py` – explain a game crash dump (exception, fault location, call stack, modules); `--latest`, `--short`, `--save-dir` (reader in `gtr2_ui/minidump.py`).
- `gtr2-lap-check.py --garage-exit` (with `--all-cars [--skip-done]`) checks only the garage exit: drives until 2 s after merging onto the pit lane, one row per car in `runs/garage_exit.jsonl`.
- `gtr2-select-wheel.py` - enables the wheel in the game's control mappings: starts the game, selects JOY1 (vJoy) on Controls > Buttons through the guarded `!SELECTWHEEL` step (`nav_paths/tour_select_wheel.txt`, `--setting-step`), closes it, then sets the pedal bindings of a preset (default `wheel-split`, the analog driver's Z/Rx). Leaves the profile changed on purpose; `--no-game` writes only the preset, `--dry-run` says what it would do.
- `gtr2_driving/controls.py` - the profile's control bindings (`Basic Controls`, `Control - Accelerate/Brake/Steer/Shift`) as named presets (`wheel-split`, `wheel-combined`), byte-preserving; `controls.py show|presets|apply NAME [--dry-run]`.
- `gtr2-axis-probe.py`: sweeps a vJoy axis in the parked cockpit and reads the game's processed input from telemetry (run via `GTR2_DRIVER_SCRIPT` with lap-check); shows how Dead Zone/Sensitivity/Center change the response.
- `gtr2-recover.py`: recovery after an interrupted run: stops stale nav servers, closes an orphaned game (`--force` kills it), reaps the launcher, `--revert` resets UserData/ReplayData in the game folder; `--dry-run`.
- `gtr2_driving/mas.py`: reads the game's `.gtr` (GMOTORMAS10) archives: `list|cat|extract`; the same format `pitzones.py` reads for the pit gates (its own older reader).
- `gtr2_driving/gmt.py`: reads `.gmt` track meshes (world-space vertices and triangles) from an archive; `garage.py`: finds the collision meshes a `.trk` lists, keeps the walls in the car's height band and predicts the clearance of a garage exit for a yaw bias.
- `gtr2-garage-map.py TRK X Z YAW`: prints the predicted clearance for yaw biases -12..12 for a garage start (offline, no game); `test_garage_map.py`: offline checks of the readers and of the Anderstorp 3 pillar prediction.
- `gtr2_driving/boxplan.py`: picks the garage-exit heading bias from the wall meshes (`--box-yaw-bias auto`, cached under `runs/box_cache/`); `gtr2_driving/box_starts.json`: every garage start the lap runner has seen, per layout and car.
- `changelog.py`: release notes from git history by day (highlights, improvements, fixes, documentation) from commit-subject tags and `changelog_overrides.json`; `--write` regenerates `CHANGES.md`, `--check` lists untagged commits.
- `publish-check.py`: pre-push privacy/safety scan of tracked files and unpushed commits (personal paths, e-mails, secrets, game file types, pictures, author identities); read-only, exit 1 on a BLOCK (see docs/publishing.md)

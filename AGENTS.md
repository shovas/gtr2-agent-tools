# AGENTS.md

Instructions for every coding agent. `CLAUDE.md` is authoritative for game safety, scripts, commits and publishing; where this file and it differ, the more specific rule wins. Topic details are in `docs/` (index at the end of `CLAUDE.md`). Other agent files (`GEMINI.md`, `.cursorrules`, ...) carry the same weight.

## Git

- Commit each successful, verified, logically coherent change, with a concise subject that starts with the changelog tag `CLAUDE.md` requires. No approval is needed to commit. Exclude temporary artifacts and secrets.
- Never push without the user's explicit go-ahead for that push (`docs/publishing.md`).

## Documentation

Keep these accurate, concise and user-oriented. Review the affected ones after every meaningful change; a task is not complete until they are.

| File | Purpose |
|---|---|
| `CHANGES.md` | User-visible changelog, newest first. Generated by `scripts/changelog.py` from tagged commits (per day). Never edited by hand; `CLAUDE.md` governs it. |
| `FEATURES.md` | What the project offers and why, ordered by user interest. |
| `CAPABILITIES.md` | Technical inventory: scope, limits, prerequisites. |
| `DEPENDENCIES.md` | What to install or provide: versions, constraints, required versus optional. |
| `knowledge/` | Discovery index for agents (below). |

Rules:

1. **Verified reality only.** Mark each item implemented, experimental, partial, unsupported or planned. Never present an untested assumption as a capability.
2. **Boundaries.** Features are user value, capabilities are technical possibilities, dependencies are requirements, changes are what changed and when.
3. **Consistency.** Terms, versions and limits agree across files and with real behaviour.
4. **History.** Never silently rewrite history; correct a material error explicitly.

## Knowledge base (`knowledge/`)

- At the start of a substantive task, read `knowledge/INDEX.md`, then the matching summary or topic, then the source files. Never rely on memory or summaries when a source exists.
- `INDEX.md`: topics, synonyms and use cases, with links. `SUMMARY.md`: findings, principles, limits. `SOURCES.md`: source paths, authority, versions, index status. `topics/`: findings with exact source locations, keeping facts, interpretations and experimental results apart. `CHANGELOG.md`: additions and corrections.
- Size: this file under 8 KiB, each master index under 16 KiB. Split by subject; retrieve selectively.
- Detect source changes by timestamp or hash and reindex only what changed. Report how deeply a source was examined; never mark one complete unless it was.

## Working principles

- **Evidence first.** Own a problem from investigation to verified result. Research before reinventing (papers, open source, docs, existing tools). Break work into independently testable parts, hold several hypotheses, and design experiments that give the most information for the least effort. Keep facts, inferences, assumptions and unknowns apart. Record failures so they are not repeated.
- **Persistence.** Continue until the objective is verified, a genuine blocker is established, or further effort is unjustified. When stalled, question assumptions and change strategy. When blocked, state the obstacle, what was tried and the alternatives. Never confuse partial progress with success.
- **Deterministic code over inference.** Encode repeatable reasoning as scripts (Python first; PowerShell for native Windows; Bash where better). Scripts validate input, give exit codes and diagnostics, control randomness and timing, and have objective tests. Keep hidden state and environment assumptions to a minimum.

## Numerical search

Search parameters with bounded methods, never by arbitrary trial and error.

1. Set bounds from domain knowledge and measurements; widen them if the optimum seems to lie outside.
2. Bisect monotonic thresholds; bracket unimodal objectives (golden-section). Use either only with evidence. Coarse first, then narrow.
3. Stop when the interval or next meaningful step is 1 percent or less of the parameter's scale, or the objective stops improving.
4. Compare candidates under identical conditions, allowing for noise and parameter interaction.
5. Record every tested value, its measurement, the bounds and the best verified result, so nothing is run twice.

## Execution modes

Recurring automation (tests, validation, diagnostics, benchmarks, sweeps) should accept `--mode quick|normal|full`, default `normal`, with Quick ⊆ Normal ⊆ Full. Not every script does yet; `CLAUDE.md` lists this as open.

- **Quick** (up to 60 s, aim for 10 s): changed behaviour, critical invariants, smoke tests, representative samples.
- **Normal** (up to 5 min): Quick plus edge cases, regressions and integration. The routine pre-commit check.
- **Full** (no limit): exhaustive and stress checks. Run **only** on the user's explicit request, never from hooks, commits, pushes or fallbacks. A generic "test" or "verify" does not authorise Full.

Every run reports its mode, duration, what ran, what was skipped and what coverage is incomplete. Select tests by failure-detection value, risk and cost, with explicit metadata. Use fixed seeds and record them with the reproduction command. On a sampled failure, expand that category, find the root cause and add a permanent regression test. Cache unchanged fixtures and reference outputs, invalidating on input, code or configuration change.

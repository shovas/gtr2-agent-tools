## What the game install is

The install is **not a source-code repository**. It is an installed copy of the Steam release of *GTR 2 – FIA GT Racing Game* (Steam app id 8790; 32-bit Windows, DirectX 9, MSVC 7.1 runtimes). It is a git repository (branch `main`) but has no build system, package manager, linter, or test suite. The binaries (`GTR2.exe`, `GTR2Config.exe`, `GTR2Dedicated.exe`, `GTR2TimeTrialInstaller.exe`, `GTR2_Reporter.exe`, `net.dll`, etc.) are closed-source and should be treated as read-only. Work here means modifying/adding game content or configuration (mods, tracks, cars, server setup).

To run: launch `GTR2.exe` (game), `GTR2Config.exe` (graphics/setup), or `GTR2Dedicated.exe` (dedicated server, native Windows UI). Nothing here can be built or unit-tested; verifying a change means launching the game.

## Layout and how the pieces fit

- `Config.ini` – written by `GTR2Config.exe`. `[COMPONENTS]` maps logical directories (`SEASONDIR=GAMEDATA\`, `TRACKSDIR=LOCATIONS\`, `VEHICLESDIR=TEAMS\`, `DRIVERSDIR=TALENT\`, `PITSDIR=SCRIPTS\`, `SAVEDIR=UserData\`, etc.) and holds graphics settings (`SHADERLEVEL`, `FSAA`, `VSYNC`, `VIDEOMODE`). Paths are relative to the install root and Windows-style. `sysinfo.txt` is a hardware snapshot generated by the config tool.
- `GameData/` – all game content, referenced from the game-mode files:
  - `*.gdb` + matching `*.txt` at the root of `GameData/` (e.g. `SIM_OFFICIAL`, `SIM_SingleMakes`, `SIM_Specials`, `24H_Spa2003`…) – **game mode/season definitions**. The `.gdb` is a plain-text key/value file (game name, filter, car categories and class mapping, drafting params, default session schedule/scoring); the `.txt` is the UI description shown in-game, using `<SET_FONT>` markup.
  - `Locations/<Track>/` – per-track files: `.gtr` (track definition), `*_LowTex.gtr`, `.AIW` (AI racing line/waypoints, one per layout variant, prefixed by layout code such as `3`, `4`, `N`, `S`, `C`), `*_LOD.jpg`, `*Thmb.tga` (thumbnail), optional `.bik` intro movie.
  - `Teams/` – cars/teams (subfolders `GT`, `NGT`, `24H`, `TrackVehicles`), shared tyre compounds (`*.tyr`), `damage.dmg`, `default.aud`; `Talent/` – drivers; `Championships/{Official,Custom}`; `Scripts/` (`pitstop.grd`, `crew.gtr`, `pitviews.cam`, the pit-stop setup); `Animations/`, `Sounds/`, `DrivingSchool/` hold the rest.
  - `Settings.ddb` – game-wide settings.
- `UIData/`, `MovieFiles/`, `Music/` – front-end assets, videos, soundtrack.
- `UserData/<ProfileName>/` – per-player profile (`.PLR` settings/controls, `.bch` benchmarks, `Career.blt`, `stats.stc`, `.gal`), plus `defviews.cam` (default camera views; `defviews_cam_BAK_*_ORIG` is a backup of the original) and `Log/`. This is user save data: do not delete or overwrite it.
- `Plugins/rFactorSharedMemoryMap.dll` – shared-memory telemetry plugin (rFactor-compatible) for external apps.
- `Support/` – EULA and docs: `GTR2_dedicated_server.txt` (dedicated server usage, lobby broadcasting, session control) and `GTR2_Server_Hosting.txt` (port allocation for multiple hosted instances on a LAN/one PC). Read these before changing server setup.
- `installscript.vdf` / `SteamInstallscript.vdf` – Steam install hooks that run `vcredist_x86.exe /passive /norestart` once per install (the former is signed; editing it breaks the signature).
- `Readme.txt` – original game readme (system requirements, MoTeC i2 telemetry, performance/troubleshooting; if the game won't start, try a different `Shader Level` in GTR2Config).

## Working notes

- Content files (`.gdb`, `.txt`, `.AIW`, `.cam`, `.grd`, `.PLR`, `Config.ini`) are text and safe to edit/diff; `.gtr`, `.gmt`, `.dds`, `.LMA`, `.tyr`, `.dmg`, `.bik` etc. are mostly binary or tool-generated. Some `.txt` files in `Support/` use legacy (non-UTF-8) encoding – preserve bytes when editing.
- Commit to git after every successful change you are confident in. The whole install (~1.6 GB, ~4000 files, mostly binary) is tracked, so `git add` specific paths for routine changes. Autocrlf is off and the tracked `.gitattributes` sets `* -text` (plus text diffs for `Config.ini`, `*.PLR`, `raceresults.txt`); do not let line endings change.
- Adding a track or car generally means adding its folder under `Locations/` or `Teams/` **and** referencing it from a `.gdb` game mode; check an existing entry as the template.

## Shared `Documents\GTR2` snapshot

Two Claude sessions (this folder and another install) can each run their own `GTR2Config.exe`, and an unelevated `GTR2.exe` reads and rewrites the single shared `%USERPROFILE%\Documents\GTR2` (Config.ini, sysinfo.txt, logs, replays, copied lessons). That folder is outside this repo, so a point-in-time copy is tracked in `_DocumentsGTR2/` (64 files; the empty `TimeTrial/` folder isn't tracked).

- Check for drift: `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/DocumentsGTR2.ps1` (lists `differs` / `only in live` / `only in snapshot`; exit 1 if any). It never writes to the live folder.
- Accept the live state as the new snapshot: add `-Update`, review `git diff _DocumentsGTR2`, then commit.
- Check this before and after anything that launches `GTR2.exe` or `GTR2Config.exe`. `Config.ini` and `sysinfo.txt` there are rewritten on every GTR2Config start. Never edit the live folder to match the snapshot without asking: the other session may rely on it.

## Launching the game from this folder (worked 2026-11-10)

`GTR2.exe` and `GTR2Config.exe` run unelevated from this folder. The VC++ 2010 x86 runtime is already installed on this machine, so the MSVCR100 error from the other install notes doesn't occur. The profile (`UserData\<profile>`, mode NOVICE) loads and the main menu appears.

- **Good config** (in the shared `Documents\GTR2\Config.ini`): `VIDEOMODE=72` (1280x720 32 bit, 60 Hz), `WINDOWEDMODE=1`, `VIDEOGUID=<adapter GUID>`, `SHADERLEVEL=0`. The game then opens a captioned window, outer 320,180 to 1606,929, client 1280x720, and leaves the 1920x1080 desktop alone.
- **What went wrong first:** the live config said `WINDOWEDMODE=1`, `VIDEOMODE=18`, but the first launch switched the whole display to 1280x720 (borderless, filling the screen) and the game rewrote the config with `WINDOWEDMODE=0` and an `[AUTOLAUNCH]` section on exit. Cause not isolated (suspect the 16 bit mode 18 entry). The game exited cleanly and Windows restored 1920x1080. Fix: run `GTR2Config.exe`, choose `1280 x 720  32 bit`, tick Windowed Mode, check the dialog, OK.
- **Scripting GTR2Config (Win32 ids):** resolution combo 1013 (44 entries; 22 to 43 are the 32 bit ones, 29 is 1280x720), refresh 1203, shader 1204, Windowed Mode checkbox 1201 (`BM_CLICK`), OK 1. Selecting with `WM_KEYDOWN`/`WM_KEYUP` VK_DOWN (0x28) on the combo works; read the selection with `CB_GETCURSEL`/`CB_GETLBTEXT` and screenshot the dialog before OK.
- **Quitting without the harness:** click EXIT at client (131,687), then the tick at client (1056,360) in the "Exit to Windows?" box. Client origin on screen is (323,206) for the window above. Use DPI-aware absolute clicks (`SetProcessDPIAware`, `SetCursorPos`, 150 ms between mouse down and up).
- **Side effects of a run:** `<profile>.PLR` is rewritten on exit (it showed `Online Server` and two FFB comment lines changing, nothing we edited), and `Documents\GTR2\Config.ini` is rewritten. Run `Tools/DocumentsGTR2.ps1` afterwards and commit.

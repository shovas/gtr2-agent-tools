## Analog driving via vJoy, lap tuning and garage exit (2026-11-11)

**Setup.** vJoy 2.1.8 (kernel driver, installed once with admin; the user approved it) gives a virtual joystick that `scripts/gtr2_driving/vjoy.py` drives from unelevated Python (`VJoy(1).axis("Z", 0..1)`; every axis is centred on acquire and release, because ResetVJD leaves sliders at 0 and the game reads that as input). The game lists it as JOY1 (Controls > Buttons); its steering/throttle/brake bars follow the axes as |value-0.5|*2, each direction a half range. Profile codes `(1, N)`: X+=1, X-=2, Y+=3, Y-=4, Z+=5, Z-=6, Rx+=7, Rx-=8. Committed bindings: steering X, Accelerate `(1, 6)` = Z below centre, Brake `(1, 8)` = Rx below centre (both at once works), shifts on vJoy buttons 1/2, `Basic Controls="0"`. To rebind: click the row (twice, the first only hovers) and move that axis while the "PRESS KEY OR CONTROLLER BUTTON" box is up. First gear still uses keyboard Q (clutch), so the game needs the focus for that one step.

**Using it.** `gtr2-lap-check.py LAYOUT --input analog [--quick] [--runs N] [--drive-args "..."]` (`--quick` stops at the first start/finish crossing, the out lap from the pits, about 3 min); `gtr2-drive-lap.py --aiw ... --fast --input analog [--tuned] [--zones] [--trace N]`. The lap runner always sets the Murcielago and writes `gtr2_ui/runs/lap_drive.log`. The control loop is plain scripted code (pure pursuit on the AIW line, speed targets from the bends ahead, proportional throttle/brake, rpm shifts); no model runs while driving. Between the commands and the axes a 100 Hz writer runs a `RackModel` per axis (damped spring on an inertia with sliding and breakaway friction, speed-capped): steering inertia 1.0, friction 1.0, stiction 1.5, wn 14; throttle `0.7 0.5 0.8 20`, brake `1.2 1.0 1.5 18` (`--analog-inertia/-friction/-stiction/-wn`, `--analog-throttle-model`, `--analog-brake-model`; inertia 0 = the older acceleration-limited `Follower`). The user asked for this so inputs look human.

**Mode and aids.** The committed `<profile>.PLR` is Novice (`Difficulty Type="0"`, auto shift, spin recovery, opposite lock and auto reverse on). The lap runner's driving profile (`DRIVING_PROFILE`, reverted with git afterwards) sets `Difficulty Type="2"` (the main menu header then reads **MODE: SIMULATION**, checked 2026-11-11), manual shift, spin recovery, opposite lock and auto reverse off, speed-sensitive steering 0.6. Steering Help 1, Brake Help 1, Stability Control 1, Auto Clutch 1, Invulnerability 1 and Damage Multiplier 100 stay on, so times are not comparable with a game without the aids. Every `lap_results.jsonl` row has a `profile` object (`MODE_KEYS` in `gtr2-lap-check.py`); rows before 2026-11-11 evening did not record it.

### Focus loss pauses the sim completely; a non-activating window does not (measured 2026-11-12)

`gtr2-drive-lap.py --focus-test START SECONDS` opens Notepad in front of the game mid-lap and reports the sim rate (distance moved / (speed x wall time)) before, during and after. **A window that takes focus stops the sim dead (rate 0.00, both with `Inactive Sleep Time` 25 and -1, so that key is irrelevant); it resumes at 1.00 when the window closes, and the lap still completes.** The same Notepad started minimised without activation (`STARTUPINFO.wShowWindow = SW_SHOWMINNOACTIVE`, env `GTR2_FT_NOACTIVATE=1`) left the rate at 1.00. So: anything the tools launch during a test must start hidden/minimised-no-activate (the nav server already runs under pythonw), and a manual window in front of the game costs sim time but not correctness. No profile or config switch for this was found.

### Driving needs vJoy (note for users of this repo)

Analog driving (`gtr2-drive-lap.py --input analog`, `gtr2-lap-check.py --input analog`, the tuner) feeds a virtual joystick. A new machine needs, once: (1) **vJoy** installed (2.1.8 used here; kernel driver, needs admin) with device 1 configured (X, Y, Z, Rx axes and at least 2 buttons); (2) the game's profile bound to it: in Controls > Buttons the game lists it as JOY1; steering X, Accelerate `(1, 6)` (Z below centre), Brake `(1, 8)` (Rx below centre), shifts on vJoy buttons 1 and 2, `Basic Controls="0"` in `UserData\<profile>\<profile>.PLR`. Rebind by clicking the row (twice, the first only hovers) and moving the axis while the "PRESS KEY OR CONTROLLER BUTTON" box is up. The game folder's tracked profile carries these bindings; a profile created on another machine does not. Keyboard driving needs no vJoy but cannot leave the garage box cleanly.

## A generic time-optimal racing line (`gtr2_driving/racingline.py`, `--line-opt`) and why it did not pay off yet (2026-11-16)

The model also ignores the combined slip of braking and cornering and the kerbs and walls inside the white lines (the Imola chicane kerb at (-5, -1) is hit hard on any line that rides it).

What it needs before it can pay: a path follower that tracks a line precisely at any speed (Stanley or model predictive: cross-track and heading error at the front axle, curvature feed-forward, a short look-ahead decoupled from speed, gains scheduled on speed), measured by the follower's own cross-track error on a fixed test line; then the optimiser's slope and radius limits can come from that measured tracking ability instead of fixed numbers. `gtr2-lap-estimate.py` and `racingline.lap_time` rank lines in seconds meanwhile.
